# PhD Assistant: System Architecture & Blueprint

> **Mission Statement**
> The PhD Assistant is a sophisticated, multi-agent AI framework designed specifically for doctoral research in the field of Technical and Vocational Education and Training (TVET). 
> It automates the agonizing process of literature review, drastically reducing noise (such as Indonesian TVET or lower-secondary school papers) and strictly enforcing relevance to Malaysian Kolej Vokasional and Generative AI pedagogy. 

This document serves as the master blueprint for the entire system, detailing the story, the "staff" (agents), the workflows, and the highly optimized anti-rate-limit architecture.

---

## 1. The Dual-Engine Architecture
The system operates on two distinct LLM engines, expertly balancing cost, speed, and analytical depth.

### Engine A: The Manual Pipeline (Gemini)
- **Primary Driver:** `src/main.py`
- **Trigger:** Manual execution via the Streamlit Dashboard.
- **Purpose:** Deep, rigorous, single-pass analysis of manually inputted literature.
- **Outputs:** Strict 4-key JSON directly into an Obsidian Knowledge Vault.
- **Quota Defense:** Utilizes a custom `QuotaManager` that dynamically rotates API keys upon exhaustion, alongside a rigid `max_rpm=10` throttle in CrewAI to prevent 429 RESOURCE_EXHAUSTED crashes.

### Engine B: The Background Scout (Groq)
- **Primary Driver:** `src/scout_groq.py`
- **Trigger:** Windows Task Scheduler (Daily at 2:00 AM).
- **Purpose:** Completely offloads daily academic scouting from the Gemini quota.
- **Model:** `qwen/qwen3.8-27b` via the Groq high-speed inference engine.
- **Quota Defense:** Groq imposes a strict 1,000 Tokens Per Minute (TPM) limit. The pipeline circumvents this by strictly capping output tokens (`max_tokens=450`) and utilizing CrewAI's `max_rpm=1` feature—forcing a 60-second delay between the Scout and the Filter agents to let the TPM quota reset organically.

## 2. The Front-End: Doctoral Command Center
**File:** `src/dashboard.py`

The system is controlled via a sleek, native Streamlit web application.
- **System Status & Metrics:** Displays active API keys, total calls used, and "Cache Hits" (saved API calls from deduplication).
- **Ingestion Portal:** Allows the user to paste abstracts or full text for the agents to review.
- **The "Open Second Brain" Integration:** A custom 1-click sidebar button that executes `run_second_brain.bat` (via `src/open_vault.py`), properly URL-encoding local Windows file paths to seamlessly launch the local Obsidian Vault.

## 3. The Staff: Agent Personas
The system utilizes a team of specialized AI agents configured in `config/agents.yaml` and `config/tasks.yaml`.

### 🧠 The Systematic Reviewer (Gemini)
- **Role:** The core TVET Literature Screener & Synthesizer.
- **Story:** A strict TVET academic reviewer who ruthlessly filters out irrelevant demographics. It executes the `comprehensive_review_task`, reading a paper and extracting the findings into a strict JSON dictionary:
  - `filename`: A smart, action-oriented name (e.g. `Paper_GenAI_Pedagogy.md`).
  - `content`: APA 7 citation, Verdict (RELEVANT/REJECT), 1-10 Score, and synthesized quotes.
  - `index_entry` & `log_entry`: Wiki-links for Obsidian tracking.

### 🧭 The PhD Co-Supervisor (Gemini)
- **Role:** Exacting and Fair UTM PhD Co-Supervisor.
- **Story:** A senior Malaysian TVET professor who challenges the researcher on academic rigor, novelty, and feasibility without pushing any specific methodology (e.g., DDR, mixed methods, quant). They enforce the strict rule that TAM/UTAUT are *methodology frameworks*, not topical literature.

### 🔎 The Groq Scouting Team
Because API limits restrict Gemini from running wild on the internet, the background scouting is handled by two dedicated Groq agents:
1. **`groq_literature_scout`:** Constantly pings the OpenAlex API for recent literature on "TVET Kolej Vokasional Teknologi Pembinaan".
2. **`groq_tvet_domain_expert`:** Aggressively filters the scout's raw results, tossing out polytechnic and SMK (Indonesian) studies before appending the survivors to `library.json`.

## 4. Anti-Hallucination & Tools
To ensure the AI does not fabricate academic references, the system utilizes custom Python `@tool` integrations.

- **`src/tools/verifier.py` (CitationVerifier):** Takes any title generated by the AI, URL-encodes it, and pings the OpenAlex API (using the `OPENALEX_MAILTO` polite pool). If the paper does not exist, the AI supervisor rejects it.
- **`src/tools/search_tools.py`:** Provides the `openalex_search_tool`, allowing agents to fetch *real* markdown-formatted literature data (DOIs, Years, Authors).

## 5. Data Flow & Output Architecture
The system employs a two-tier storage approach.

1. **The Append-Only Database (`output/library.json`)**
   - The central nervous system. The Groq scout and the Gemini pipeline both check this file before executing. If a paper's title already exists in this database, the system triggers a **Cache Hit**, instantly returning the previous analysis and saving API quota.
   
2. **The Obsidian Vault (`output/Obsidian_Vault/`)**
   - Once the `systematic_reviewer` outputs its 4-key JSON, the Python backend physically writes the data into a structured folder hierarchy for Obsidian:
     - `02_Wiki/{filename}.md`: The actual synthesized paper.
     - `03_System/index.md`: A bulleted master index of all accepted papers, automatically updated.
     - `03_System/log.md`: A timestamped action log of agent behavior.
